# 部署与运维

这份文档讲的是「跑起来之后」的事：怎么开机自启、怎么对外发布、怎么轮换 token、出问题怎么查。快速开始请看根目录的 [README](../README.md)。

---

## 1. 进程管理（Windows）

仓库里带三个脚本，都放在 `server/`：

| 脚本 | 作用 |
| --- | --- |
| `start-share-site.ps1` | 后台启动，写 `run\share-site.pid`，日志写到 `logs\` |
| `stop-share-site.ps1` | 按 pid 文件 + 端口监听查找并停止 |
| `status-share-site.ps1` | 显示端口、PID、公网地址，并请求 `/healthz` |

```powershell
powershell -ExecutionPolicy Bypass -File server\start-share-site.ps1
powershell -ExecutionPolicy Bypass -File server\status-share-site.ps1
powershell -ExecutionPolicy Bypass -File server\stop-share-site.ps1
```

日志：

- `server/logs/share-site.out.log` —— 启动信息、正常输出
- `server/logs/share-site.err.log` —— 异常堆栈

端口从 `config.json` 的 `port` 读取；改了端口要 stop 再 start。改 `config.json` 的任何字段都需要重启才生效（`config.js` 在启动时一次性读取）。

### 登录时自动启动

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install-autostart.ps1
# 卸载
powershell -ExecutionPolicy Bypass -File scripts\install-autostart.ps1 -Uninstall
```

原理：在用户 Startup 文件夹放一个 `.lnk`，指向 `wscript.exe` 执行生成的 VBS，VBS 延迟 15 秒后用隐藏窗口拉起 `start-share-site.ps1`。全部是用户级操作，不需要管理员权限。

想换成 Windows 服务（NSSM、计划任务「登录时」）也可以，脚本本身不关心是谁拉起的。

## 2. 对外发布

服务默认绑定 `127.0.0.1`。**不建议**直接把 `host` 改成 `0.0.0.0` 暴露到公网——那样等于把 token 当作唯一防线。

### 2.1 反向代理

Nginx 片段：

```nginx
location /s/ {
    proxy_pass http://127.0.0.1:8010;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Real-IP $remote_addr;
}

location /assets/ {
    proxy_pass http://127.0.0.1:8010;
    proxy_cache_valid 200 1h;
}
```

Caddy 更省事：

```caddy
share.example.com {
    handle /s/* {
        reverse_proxy 127.0.0.1:8010
    }
    handle /assets/* {
        reverse_proxy 127.0.0.1:8010
    }
    respond 404
}
```

要点：

- **只转发 `/s/` 和 `/assets/`**，`/api/link` 留给本机扩展用，不必对外；
- 反代层补上 HTTPS；
- 如果反代做了路径前缀改写，`baseUrl` 要跟着改。

### 2.2 隧道

Cloudflare Tunnel：

```bash
cloudflared tunnel --url http://127.0.0.1:8010
```

把它跑成服务，再在 Cloudflare 侧给域名加 Access 策略（邮箱白名单 / OTP），这样即使 token 泄露也多一层门槛。

frp 也可以，但注意：**只映射 8010 这一个端口**，并且把 `frpc` 的访问限制在服务器侧的安全组里。顺手映射的 `8004` 之类调试端口，很容易变成绕过鉴权的后门。

### 2.3 健康检查

```bash
curl http://127.0.0.1:8010/healthz
# {"ok":true,"service":"share-site"}
```

这个接口不校验 token，可以给探活用；它不泄露任何目录信息。

## 3. 轮换 token

```powershell
node -e "console.log(require('crypto').randomBytes(24).toString('base64url'))"
```

1. 把新值写进 `config.json` 的 `token`；
2. 重启服务；
3. VS Code 扩展不用改——它每次生成链接时都重新读 `config.json`；
4. 旧链接会立刻返回 404。

建议在以下情况轮换：怀疑链接被转发到公开群、设备丢失、把某篇笔记发给了不该看的人。

> `data/links.json` 里的短 id 与 token 无关，轮换后 id 仍然有效，只是入口前缀变了。

## 4. 新增 / 关闭分享目录

编辑 `config.json` 的 `roots`：

```json
{ "name": "work", "path": "D:\\work\\docs", "enabled": true }
```

- 关闭一个目录：`enabled: false`，重启即生效，该目录下的所有短链接都变成 404；
- 改名会改变 URL 第一段，旧链接失效——短 id 是按 vpath 算的，`name` 变了 vpath 就变了；
- `path` 必须存在且是目录，否则启动时被跳过（日志里会有 `跳过不存在的目录`）。

默认排除规则（不需要手写）：以 `.` 开头的名字、`.git`、`node_modules`、`__pycache__`、`.venv`、`Thumbs.db`、`desktop.ini` 等。额外的排除项写在 `exclude` 里。

## 5. 短链接维护

短 id 存在 `server/data/links.json`：

```json
{
  "AbCd1234": "notes/测试/示例.md"
}
```

- 文件上限 50000 条，写入是防抖 + 原子替换（先写临时文件再 rename），断电不会写坏；
- 删掉这个文件会重新分配 id，**所有已发出的短链接都会失效**，一般不要动；
- 想手动清掉某条，停服务后编辑 JSON 再启动即可（不保证 id 不会被重新分配出去）。

## 6. 排障

| 现象 | 先查什么 |
| --- | --- |
| 页面 404「分享链接无效」 | 路径里的 token 和 `config.json` 是否一致，注意 URL 编码 |
| 页面 404「文件不存在」 | 文件是否在**启用的** root 下；文件名里有没有被排除的前缀 |
| 首页目录列表是空的 | `path` 是否写错、是否被 `exclude` 排除 |
| 样式没更新 | `public/` 下的文件有 `?v=<mtime>`，**改完 CSS 必须重启**才换版本号 |
| 扩展提示「不在分享目录内」 | 扩展读的 `config.json` 和站点用的不是同一份；检查 `shareSite.configPath` |
| 扩展生成的是长链接 | 本机服务没起、端口不一致，或 `/api/link` 超时（1.2 秒） |
| 深色主题下笔记里的颜色看不清 | 检查颜色是否被归到了 `md-tc-*` / `md-hl-*`，以及对应 CSS 变量 |
| 启动失败 | 看 `logs/share-site.err.log`；最常见是端口被占或 JSON 里有中文引号 |

常用检查：

```powershell
# 端口是谁在占
Get-NetTCPConnection -LocalPort 8010 -State Listen | Select-Object OwningProcess

# 看最后 50 行错误
Get-Content server\logs\share-site.err.log -Tail 50

# 不启动服务，只校验配置
cd server; node -e "import('./lib/config.js').then(()=>console.log('config ok'))"
```

## 7. 备份

需要备份的只有三样：

1. `server/config.json`（含 token，别放公开位置）；
2. `server/data/links.json`（保住已发出去的短链接）；
3. `roots` 指向的真实内容本身（这个不归本站管）。

`logs/`、`run/` 都可以随时删。
